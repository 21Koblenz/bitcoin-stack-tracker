LIVE MEMPOOL TEST · TOR-REGELN GELTEN

Öffentliche Transaktion als Test verwenden

Optional kannst du eine beliebige öffentliche Bitcoin-TXID prüfen. Ist deine eigene mempool-Instanz konfiguriert, wird ausschließlich sie verwendet. Nur ohne eigene/custom Node kann eine bereits konfigurierte öffentliche Mempool-Quelle nach ausdrücklicher Tor-Freigabe genutzt werden. Die Transaktion wird nicht als deine Wallet gespeichert.

Die Testmeldung ist deutlich als TEST gekennzeichnet. Falls du Home-Assistant-Automationen auf das Sentinel-Event gelegt hast, können auch diese durch die Simulation oder den Live-Test ausgelöst werden.

MONITOR SETTINGS

Überwachung & Benachrichtigungen

Lokale/private Fulcrum- oder electrs-Ziele werden direkt angesprochen. .onion und öffentliche Hostnamen laufen ausschließlich über den integrierten Tor-SOCKS5-Proxy mit Remote-DNS.

Harte Sentinel-Regel: Eine explizit ausgewählte Quelle ist exklusiv. Fulcrum/electrs down = Sentinel offline/teilweise, ohne Wechsel auf Mempool oder Public. Eigene Mempool-Node down = ebenfalls kein Provider-Fallback. „Automatisch“ wählt anhand der Konfiguration: eigener Fulcrum/electrs → eigene Mempool-Node → nur wenn keine eigene Quelle vorhanden ist und Tor freigegeben wurde eine konfigurierte öffentliche Mempool-Quelle.

Tor verbirgt bei einer öffentlichen Quelle deine Anschluss-IP, nicht aber die abgefragten Bitcoin-Adressen. Für maximale Privatsphäre eine eigene lokale Fulcrum-/electrs- oder Mempool-Instanz verwenden.

Home-Assistant Notify-Dienste
MULTI CHANNEL

Weitere Benachrichtigungsziele

Mehrere Ziele können parallel verwendet werden. Lokale Ziele gehen direkt im LAN; öffentliche Ziele und Onion-Dienste ausschließlich über Tor. Kein Clearnet-Fallback.

Wallet hat Vorrang: Bei Wallet-Alarmen bestimmt immer die Einstellung der jeweiligen Wallet oder Adresse (Diskret · Normal · Detailliert) den Inhalt. Die Server-Einstellung ist nur die Vorauswahl beim erstmaligen Anlegen einer neuen Wallet.

Für öffentliche ntfy/Webhook-Ziele gilt Tor-only. TLS-Prüfung darf nur bei lokalen oder Onion-Zielen abgeschaltet werden. Zugangstoken werden im verschlüsselten Monitor-Cache benötigt, damit Benachrichtigungen auch bei gesperrtem Tresor nach einem Neustart funktionieren.

WATCH TARGETS

Überwachte Wallets & Adressen

Alle neu von Sentinel erkannten Bewegungen werden unabhängig von der Alarmgrenze im lokalen Journal protokolliert. Die separate TX-Übersicht darf zusätzlich ältere Blockchain-Historie anzeigen; diese rückwirkend geladenen Transaktionen erzeugen keinen Alarm und werden klar von echten Sentinel-Erkennungen unterschieden. Die historische Übersicht bleibt flüchtig im RAM und wird nicht dauerhaft gespeichert. Mit 0 ist keine Mindestgrenze aktiv.

SECURITY BOUNDARY

Datenschutzstatus

Watch-only-Daten können keine Bitcoin ausgeben, verraten aber echte Bestände und Aktivität. XPUB/ZPUB/Descriptor/Adressen sind Watch-only-Material und werden zusätzlich im separaten device-bound AES-256-GCM-Sentinel-Tresor gespeichert, damit Wallets auch bei gesperrtem Portfolio-Tresor verwaltet werden können. Seeds, xprv/yprv/zprv und Private Keys werden niemals akzeptiert. Konkrete abgeleitete Adressen, Saldenstatus und das Sentinel-Journal liegen ebenfalls in diesem verschlüsselten Sentinel-Tresor. Die historische TX-Übersicht wird nicht dauerhaft gespeichert.
